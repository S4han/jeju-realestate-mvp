### 문서에서 찾은 공백 및 결정 필요 사항
1. **상업적 이용 여부 미정**: Vercel Hobby는 비상업용만 허용한다(§3). 광고·후원을 넣을 계획이 있는지에 따라 호스팅 후보가 바뀐다. → **사용자 결정 필요**
2. **현재 월 데이터의 불완전성**: 실거래 신고 기한이 계약 후 30일이므로 현재 월과 직전 월 데이터는 계속 늘어난다. "거래 없음"과 "신고 기한 미도래"를 구분해서 안내해야 한다(PRD의 '거래 없음/누락 구분' 원칙을 확장한 것).
3. **해제(취소) 반영 주기**: 해제는 계약 후 수개월 뒤에도 반영될 수 있다 ❓. 일일 증분은 최근 3~4개월을 다시 수집하고 과거 월은 주 1회 재검증하는 방식을 제안한다.
4. **EXT-006 좌표 소스 미정**: 후보는 카카오 로컬(주소→좌표), 행안부 도로명주소 좌표 API, 단지정보 자체 좌표 ❓. 이 중 **좌표를 DB에 저장해도 되는지**(약관)가 핵심 판단 기준이다.
5. **배치 실행 환경 미정**: Vercel Cron, GitHub Actions 스케줄, DB 공급자 스케줄러 중 무엇을 쓸지 정해야 한다. 무료 한도 확인이 필요하다.

## 2. 외부 API 검증 계획 (승인 후 실행)

### 2.1 사전 확인된 사항 (문서 기준)
- R-001 아파트 매매(data.go.kr 15126469): 개발계정 일일 트래픽 **10,000건**, 활용사례를 등록하면 운영계정으로 증설 가능 ✅(공식 페이지). 다만 블로그에는 1,000건이라는 기록도 있다 ⚠️ → **신청 후 마이페이지 값으로 확정**.
- 한도 초과 시 에러코드 22(일일 허용량 초과)를 받고 호출이 차단된다 ✅ → **과금은 발생하지 않는다** (공공데이터포털은 무료).
- R-002 전월세(15126474): 법정동코드 앞 5자리 + 계약년월 6자리로 조회하며, 동·호 정보는 제외된다 ✅.

### 2.2 실거래 응답에서 확인할 가설 ❓
| 가설 | 왜 중요한가 |
|---|---|
| 단지 일련번호(예: `aptSeq`) 필드 존재 | 매칭 1순위 키. 없으면 법정동+지번+단지명 조합으로 매칭 |
| 지번(본번/부번)·법정동코드·도로명 필드 존재 | 주소 기반 매칭 |
| 해제여부/해제사유발생일 필드 존재 | 취소 반영 방식 |
| 금액 단위 '만원' + 콤마 포함 문자열 | 원 단위 정수로 정규화 |
| 원천 고유키 부재 | 중복 판정 복합키 설계 필요 |
| `numOfRows` 최대값과 `totalCount` | 페이지네이션 및 호출량 산정 |
| 전월세의 계약구분(신규/갱신)·종전 보증금 필드 | 표시 범위 결정 |

### 2.3 호출 예산 (승인 요청 대상)
| 단계 | 호출 수(최대) | 내용 |
|---|---|---|
| ① 스모크 | 4 | 제주시·서귀포시 × 매매·전월세 × 직전 완결 월 1개, `numOfRows` 소량 |
| ② 페이지네이션/한도 | 4 | 같은 월을 큰 `numOfRows`로 호출해 `totalCount`와 최대 페이지 크기 확인 |
| ③ 오류 동작 | 2 | 잘못된 지역코드·미래 월로 오류/빈 응답 형식 확인 |
| ④ 해제 거래 확인 | 4 | 과거 월 1개(예: 6개월 전)에서 해제 표기 샘플 확보 |
| **합계** | **≤ 14** | 일일 한도(1,000~10,000) 대비 1.4% 이하 |

운영 시 예상치(가설): 초기 전체 수집 48호출 + 페이지네이션 여분, 일일 증분 16호출(2시 × 2유형 × 최근 4개월), 주간 재검증 48호출 → **일 100건 미만**.

### 2.4 단지·좌표 (EXT-003/004/006)
- 부동산원 단지 기본정보, K-APT 단지 목록: 활용신청 필요. 제주 단지 수, 식별자 체계, 주소 필드, 갱신주기, 재배포 조건을 확인한다. 호출 예상은 소스당 10건 이하.
- 좌표: 소스를 정한 뒤 샘플 20개 단지를 수동 대조해 정확도를 확인한다. **좌표 저장 허용 여부를 약관 원문으로 확인**한다.

### 2.5 실행 원칙
- 키는 환경 Secret으로만 주입하고 존재 여부만 확인한다(값 출력·로그·커밋 금지). 요청 URL을 로깅할 때는 `serviceKey`를 마스킹한다.
- 원본 응답은 저장소에 커밋하지 않는다. 필드 목록과 익명 샘플 1~2건만 문서화한다.
- 결과는 날짜, 호출 수, 성공/실패, 미해결 위험과 함께 `docs/API_VERIFICATION.md`에 기록한다.

### 결론 (잠정)
- **월 0원 운영은 가능성이 높다.** 단 다음 조건을 지켜야 한다.
  1. 카카오 앱에 **비즈월렛을 연결하지 않는다**. 초과 시 과금이 아니라 차단되게 두고, 차단되면 목록 검색으로 대체한다(FR-008).
  2. 카카오맵 API를 활성화하는 앱이 해당 개발자 계정에서 **첫 번째 앱**이어야 무료 쿼터가 붙는다. 기존 앱이 있으면 무료 쿼터를 받는 앱부터 확인한다.
  3. 상업적 이용(광고·후원 포함)을 하면 Vercel Hobby를 쓸 수 없다.
  4. 모든 DB·호스팅 계정에 결제수단을 등록하지 않는다. 등록이 필요한 공급자는 탈락시킨다.
- 마지막 검증 지점: "비즈월렛 미연결 상태에서 쿼터를 초과하면 실제로 차단되는가"는 문서만으로 단정할 수 없다. 카카오 콘솔의 쿼터 화면과 공식 FAQ로 확인한다(GATE A).

### 지도 선택지 (사용자 결정 필요)
1. **PAW_MAP 앱의 JavaScript 키를 함께 사용(권장)**: PAW_MAP 앱의 Web 플랫폼에 이 서비스 도메인을 추가한다. 무료 쿼터(지도 SDK 일 30만, 월 전체 300만)를 PAW_MAP과 나눠 쓴다.
   - 확인 필요: PAW_MAP의 [통계 > 쿼터]에 무료 한도 막대가 보이는지, 비즈월렛이 연결되지 않았는지, PAW_MAP의 현재 사용량.
   - 위험: 한 앱을 두 서비스가 쓰는 데 대한 공식 정책 문구는 확인하지 못했다(위반으로 명시한 것은 '여러 앱을 만들어 쿼터를 늘리는 행위').
2. **무료 쿼터 이관**: 데브톡 요청으로 쿼터를 새 앱으로 옮긴다. PAW_MAP은 무료 쿼터를 잃는다. 처리 결과가 확인된 사례가 없다.
3. **Leaflet + VWorld 배경지도**: 과금 구조 자체가 없다. VWorld 키 발급이 필요하고 이용조건 확인이 필요하다. 카카오맵 우선이라는 PRD 결정에서 벗어난다.
- 새 카카오 앱 생성 + 비즈월렛 연결은 월 0원 원칙에 따라 **선택하지 않는다**.
