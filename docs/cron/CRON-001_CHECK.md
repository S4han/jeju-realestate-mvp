## 2. 한 번 실행 시 하는 일
1. `Authorization: Bearer $CRON_SECRET` 아니면 401(외부 호출 0). Vercel은 `CRON_SECRET`이 설정되면 예약 요청에 이 헤더를 붙인다.
2. 설정 검증 실패(키 없음 등) → 503 `COLLECTOR_MISCONFIGURED`, 변수 **이름만** 로그(외부 호출 0).
3. 매매·전월세 × 제주시·서귀포시 × 최근 4개월 = 16개 작업. 월 단위로 모든 페이지를 받아야만 반영(트랜잭션), 실패한 달은 기존 데이터 유지 + `sync_jobs`에 FAILED 기록.
4. 호출 상한: 실행당 30회, 출처별 하루 300회(`api_usage`, PC 수집과 공유). 재시도(2초·5초 후 2회)도 상한에 포함.
5. 매칭: 전체 거래를 다시 판정(외부 호출 없음).

## 4. 실행 시간 — 운영 기록으로 확인 필요 (⬜)
- 실행 시간 ≈ 호출 수 × data.go.kr 응답 시간 + 반영·매칭. 호출 20회에 응답 1.5초면 약 32초, **3초면 60초 제한 초과**.

## 6. 가동 절차 (승인 후, 단계마다 확인)
1. 사용자 PC: `cron-check.ps1` 실행(읽기 전용) → 실제 소요 시간 확인.
2. (D1·D2 승인 시) 코드 수정 → 테스트 → Production 배포(플래그·비밀값 없음 상태라 Cron은 계속 401).
3. 사용자: Vercel → Settings → Environment Variables, Production 전용 sensitive로 `DATA_GO_KR_SERVICE_KEY`(PC에서 쓰는 키), `CRON_SECRET`(32자 이상 임의값) 입력 → 재배포.
4. 첫 실행: Vercel → Settings → Cron Jobs의 수동 실행(⬜ 버튼 위치 확인) 또는 다음 03시 예약 실행. 확인: 런타임 로그(응답 요약: 호출 수·작업 상태·매칭), `/api/system/data-status`, 지도·지역 분석 데이터 버전 변경.
5. 3일 관찰: 매일 성공·소요 시간·호출 수. 이상 없으면 PC 일일 수집 중단, `OPERATIONS.md` 갱신.
- **즉시 중단**: `CRON_SECRET` 삭제 + 재배포 → 401, 외부 호출 0(로컬 1번 검증).
