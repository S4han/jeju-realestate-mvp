# Phase 3 — Claude Code 구현 계획

> 상태: STEP 6 최종 승인 반영 / 문서 확정. 실제 API·DB·공급자 요금·경계 라이선스 검증 및 개발·테스트는 **미수행**이며 Claude Code 책임 작업.
> 변경 경계: **docs/phase3/** 및 **tasks/phase3/** 신규 파일만. Phase 1·2 기존 파일·API·데이터 변경 금지. 기능 플래그 기본 OFF, 공개 전 사용자 수동 승인.
> 기준: 한국시간(Asia/Seoul), 아파트 **매매** 계약일 기준. 샘플 숫자는 실거래 아님.

## 2. Claude Code 실행 지침
1. 먼저 저장소 실제 코드와 docs/phase2/ 전체를 읽고 현재 구현 상태와 PRD 가정 차이를 보고한다.
2. Phase 1·2 기존 파일은 수정하지 않는다. 구현 시 불가피한 기존 코드 변경이 필요하면 **사전에 변경 파일·이유·영향·대안**을 제시하고 사용자 승인 전 변경하지 않는다.
3. 실제 API 제공 여부·요금·인증·호출 제한·응답 필드·경계 이용조건을 문서/샘플로 검증하되 Secret은 출력하지 않는다.
4. TASK를 순차 실행하고 단계별 검증 증거와 승인 요청. 구현 중 API·DB·배포는 각 단계의 사용자 승인 및 환경 허용 범위 내에서만 진행한다.
5. Phase 3 기능 플래그는 기본 OFF, 공개 배포·유료 자원 사용 금지. 테스트 증거를 정리하고 최종 사용자 수동 승인 대기.

## 3. 완료 정의
P3-FR-001~024, NFR-001~007 수용 기준 충족, P3-TC-001~040 통과, 원본/지역/지도 버전 정합, 48시간·비용 장애 대체, Phase 1·2 회귀 통과, 비용 상한 검증, 수동 공개 승인 전까지 OFF.
