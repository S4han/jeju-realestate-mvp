## 1. 구현 (`server/phase3/statistics.ts`, 신규)
| 항목 | 규칙 |
|---|---|
| 대상 거래 | Phase 2와 같은 유효 매매(ACTIVE·가격>0·면적>0·확정 매칭) 중 지역 매핑 **MAPPED**만(`mapping.ts`) |
| 거래량 | 지역×계약월 건수를 기간 월만큼 합산(월별 집계 → 기간 합) |
| 가격 | 기간 원본 거래의 `sale_price / area_m2`(정밀 면적, numeric 정확 연산) 중앙값, 짝수는 가운데 두 값 평균(`percentile_cont(0.5)`). 월별 중앙값 재집계 없음. 화면 표시용으로만 원 단위 반올림 |
| 표본 | 3건 이상 AVAILABLE, 1~2건 INSUFFICIENT_SAMPLE(건수만), 0건은 수집 완전 시 NO_TRADES, **아파트가 없는 지역은 NO_APARTMENTS**(0건과 구분), 수집 누락·일부 월 포함 시 INCOMPLETE_DATA(가격 null, 건수 `countStatus=INCOMPLETE`) |
| 변화율 | 최근 12개월(현재 월 포함) vs 직전 12개월 원/㎡ 중앙값, 양쪽 3건 이상 + 24개월 모두 수집 완전. 12개월 화면에서도 24개월을 읽음 |
| 시 통계 | 시의 MAPPED 원본 거래에서 직접 중앙값(읍면동 중앙값 평균 아님). 시별 격리 건수 `unmapped`(미매칭·코드 충돌·세트 외)와 `total` 제공 → **시 합계 = 읍면동 합 + 격리분** |
| 완전성 | `sync_jobs` 시·계약월별 최신 상태(Phase 2 규칙). 한 시의 누락은 그 시 지역에만 영향 |
| 최신성 | 마지막 정상 수집 48시간 초과 STALE, 현재 월 잠정(`provisionalCurrentMonth`, `currentMonth`) |
| snapshotId | `세트ID-지문16자`: 지역 세트 + 기간 내 모든 유효 거래(금액·면적·계약일·매핑 상태·지역) + 수집 상태의 md5. 같은 데이터면 같은 값, 거래 추가·취소·세트 변경 시 변경 |
| 월별 시계열 | `loadRegionMonthly`: 수집 누락 월은 null(0 아님), 현재 월 표시 |

## 3. 성능 (로컬, 운영 규모 합성 거래 6,938건 + 실제 지역 세트, 30회)
| 조회 | p50 | p95 |
|---|---|---|
| 시 2곳, 24개월 | 32ms | 34ms |
| 제주시 읍면동 47곳, 12/24/36개월 | 41/44/53ms | 51/58/63ms |
| 서귀포시 읍면동 27곳, 36개월 | 44ms | 48ms |
→ 목표(p95 1,000ms) 대비 6% 이하. 거래를 여러 번 읽는 구조라 필요하면 단일 쿼리로 줄일 여지 있음(현재 불필요).
- 합성 DB는 단지가 한 법정동에 몰려 있어 서귀포시 거래가 "코드 충돌"로 격리됨(합성 데이터 특성). 실제 분포는 운영 실측(P3-TASK-001 10절)과 같을 것으로 예상, P3-TASK-005 이후 운영 적재 후 대사로 확인.

## 4. 문서와의 차이·남은 사항
- 시 거래량: 문서 "시 = 하위 확정 + 미매핑". 구현은 `tradeCount`(MAPPED, 가격·지도 색 기준)와 `unmapped.total`(격리 포함 전체)을 **둘 다** 제공 — 가격은 확정 단지 거래만(TC-024 "미확정 단지 제외")으로 계산하기 때문. 화면 표기 방식은 P3-TASK-006에서 확정.
- 5분위·범례·API 응답 형식은 P3-TASK-005.
- 운영 데이터 대사(시 합계·읍면동별 건수)는 운영 적재 후 수행.
