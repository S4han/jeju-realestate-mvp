# Phase 2 Claude Code 개발 이관 계획

> 상태: 최종 승인 반영 설계 문서 / 실제 API·DB·요금제 검증 및 구현 미수행. Claude Code에서 현행 코드 확인 후 수행.
> 범위: Phase 2 신규 파일만 추가. Phase 1 파일 수정 금지. 기능 플래그 기본 OFF. 사용자 수동 공개 승인 필수.

## 절대 금지
Phase 1 파일 덮어쓰기(아래 예외 제외)·기존 API 계약 변경·실제 운영 DB 무단 변경·비밀키 출력·과금 가능한 서비스 무승인 사용·기능 플래그 임의 ON·사용자 승인 없는 공개 배포 금지.

## Phase 1 연결 부위 예외 (D4, 2026-10-25 사용자 승인)
상세 화면에 가격 분석 탭을 붙이기 위해 아래 Phase 1 파일에 한해 **기능 플래그로 감싼 최소 연결 코드**만 허용한다.
| 파일 | 허용 범위 |
|---|---|
| `src/components/TransactionsPage.tsx` | 탭 목록에 "가격 분석" 탭 1개 추가, 탭 내용은 Phase 2 신규 컴포넌트(`PriceAnalysis.tsx` 등) 렌더링 |
| `server/dev-server.ts` | 로컬 개발용 `/api/v2/analysis/...` 경로 등록 |

규칙: (1) 위 목록 외 Phase 1 파일은 수정 금지, 필요 시 사전 승인. (2) 기존 API 경로·응답 계약 변경 금지 — Phase 2 API는 `/api/v2/analysis/...` 신규 함수(단일 함수, D5)에만. (3) 플래그 OFF(`PHASE2_PRICE_ANALYSIS_ENABLED` 미설정/false)면 v2 API는 404, 화면은 분석 상태 API가 사용 가능일 때만 탭 표시 → OFF 시 Phase 1과 동일 동작. 탭 표시 여부는 **서버 상태 API로 판정**(빌드 시점 `VITE_` 플래그 미사용, 노출 검사 허용 목록 수정 불필요). (4) 기존 단위·통합·E2E 테스트 전부 통과 + 플래그 OFF 시 탭 미표시·v2 데이터 API 미호출 테스트 추가. (5) Phase 1 파일 diff 전체를 P2-TASK-005 보고서에 첨부하고 G4에서 승인.

## 실행 순서 / 작업
1. P2-TASK-001 현행 저장소/스키마/API/무료 한도 **검증 계획과 차이 보고** (실행은 Claude Code에서).
2. P2-TASK-002 Phase 2 데이터 모델·안전한 마이그레이션/롤백 설계.
3. P2-TASK-003 유효 거래·월별 집계·원본 기간 통계·버전 처리.
4. P2-TASK-004 분석 API·근거 거래 커서·캐시/보안.
5. P2-TASK-005 기존 상세에 가격 분석 탭·반응형·접근성.
6. P2-TASK-006 30개 TC·데이터 품질·Phase 1 회귀·성능 검증.
7. P2-TASK-007 비용·장애·플래그·배포 게이트 증거 정리 후 **사용자 승인 요청**.

## 단계별 확인 게이트
G1 현행 스키마/API/원천 응답/무료 한도 확인 → 사용자에게 차이·위험 보고. G2 마이그레이션 리뷰. G3 집계·캐시 일관성 검증. G4 UI/회귀 검증. G5 비용·장애·수동 배포 승인. 각 게이트 전 후속 위험 작업 보류.
