## 4. 대안 B 상세 설계
### 4.1 유효 거래(공통 정의, 한 곳에서만 정의)
`trade_type='sale' AND record_status='ACTIVE' AND apartment_id = :id AND contract_date >= :from AND contract_date < :to`, 면적 유형 `floor(area_m2) = :area`(PRD v1.2). `apartment_id`는 CONFIRMED 매칭에서만 채워짐(운영 DB 일관성 위반 0건, P2-TASK-001 8절) → AC-015는 이 규칙 + 회귀 테스트로 보증. 같은 조건 거래는 각각 포함(v1.3).

### 4.2 기간·완전성·최신성
- 기간: KST 현재 계약월 포함 N개월(12/24/36), `[시작월 1일, 다음달 1일)`. 기존 `server/collect/months.ts` 재사용(읽기만).
- 완전성: 단지의 시(city_code)에 대해 `sync_jobs`(MOLIT_SALE)의 계약월별 **최신 작업 상태**. SUCCESS → COMPLETE, PARTIAL → 잠정(일부 행 읽기 실패), FAILED/없음 → INCOMPLETE(그 달 0건을 "거래 없음"으로 표시 금지). 별도 coverage 테이블 불필요.
- 최신성: 해당 시 MOLIT_SALE 최신 성공 `completed_at`이 48시간 초과면 STALE(PRD). 현재 계약월은 잠정 표시.
- 변화율: 최근 12개월·직전 12개월 각 3건 이상 **그리고** 두 구간 모든 월 COMPLETE일 때만.

### 4.3 데이터 버전·캐시·커서
- `dataVersion` = `md5(유효 거래 (id, 금액, 면적, 계약일) 정렬 목록 | 해당 시·기간 sync_jobs 최신 (월, 상태, 완료 시각))`의 앞 16자. **API_SPEC의 bigint → 문자열로 변경 필요.**
- 응답의 모든 부분(요약·분기·월별 거래량·점·근거)은 같은 트랜잭션에서 계산하고 같은 `dataVersion`을 담는다.
- 근거 거래 커서 = (단지, 면적, 기간, 정렬, dataVersion, 마지막 (contract_date, transaction_id)) + HMAC 서명(서버 비밀값 `P2_CURSOR_SECRET`). 다음 페이지 요청 시 버전을 다시 계산해 다르면 **409 DATA_VERSION_CHANGED**.
- 캐시: 공유 캐시 없이 CDN `s-maxage`(300초)로 URL 단위 캐시. 원본 갱신은 하루 1회라 최대 5분 지연 허용. 인스턴스 메모리 캐시는 쓰지 않음.

### 4.4 안전장치
- Phase 2 쿼리는 모두 `BEGIN ISOLATION LEVEL REPEATABLE READ READ ONLY`로 실행 → **코드 결함이 있어도 DB를 바꿀 수 없음**.
- 파라미터 바인딩, 면적·기간·페이지 크기 서버 검증, 문 단위 타임아웃(`statement_timeout` 예: 2초)으로 공용 DB 보호.
- 플래그 OFF(`PHASE2_PRICE_ANALYSIS_ENABLED` 미설정/false)면 DB 접근 전에 404.

## 5. 마이그레이션·롤백
- **대안 B: 마이그레이션 없음.** Phase 1 테이블·인덱스 변경 없음, 새 객체 없음 → 롤백 대상 없음(기능 플래그 OFF가 곧 롤백).
- 필요 인덱스: Phase 1 기존 `transactions_apartment_date_idx (apartment_id, contract_date DESC) WHERE apartment_id IS NOT NULL`로 충분(실측). 추가 인덱스 불필요.
- PK/NULL/all 처리: 저장 테이블이 없으므로 "area_type NULL 복합 PK" 문제 자체가 없음. `all`은 면적 조건 없이 월별 건수만 계산하고 가격 필드는 null(PRD).
- 대안 A를 택할 경우의 테이블·순방향/롤백 SQL은 이 문서 승인 결과에 따라 작성(현재 미작성).
