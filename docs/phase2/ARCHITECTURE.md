# Phase 2 집계·API·캐시 아키텍처

> 상태: 최종 승인 반영 설계 문서 / 실제 API·DB·요금제 검증 및 구현 미수행. Claude Code에서 현행 코드 확인 후 수행.
> 범위: Phase 2 신규 파일만 추가. Phase 1 파일 수정 금지. 기능 플래그 기본 OFF. 사용자 수동 공개 승인 필수.

## 데이터 흐름
Phase 1 기존 수집 → 정규화·매칭 확정(Phase 1 테이블) → /api/v2/analysis/...가 요청 시 읽기 전용으로 계산(v1.5) → 가격 분석 탭. 화면 조회마다 국토부 원천 API 직접 호출 금지.

## 혼합 집계
월별 거래량 그래프: 원본 유효 거래의 월별 건수(v1.5, 사전 집계 없음). 가격 그래프(v1.1): 선택 면적의 유효 원본 거래 점 + 분기 중위 보조선(분기 3건 이상). 기간 전체 중위/최저/최고/㎡당 통계 및 12개월 비교: 동일 버전 유효 **원본 거래** 계산. 전체 면적은 거래량만. 유효 거래 정의는 코드 한 곳에서만 정의해 모든 쿼리가 공유.

## 일관성
(v1.5) 한 응답의 요약·분기·월별 거래량·점·근거·완전성은 `REPEATABLE READ READ ONLY` 트랜잭션 하나에서 계산하고 같은 데이터 버전(지문)을 담는다. 근거 페이지 커서는 버전을 포함, 다음 페이지에서 재계산한 버전이 다르면 409 DATA_VERSION_CHANGED. CDN 캐시(s-maxage)는 URL 단위, 원본 갱신 주기(1일) 대비 최대 5분 지연 허용. 쿼리 시간 제한으로 공용 DB 보호.

## 기능 격리
PHASE2_PRICE_ANALYSIS_ENABLED=false 기본. UI와 서버 API 양쪽에서 검증. Phase 1 라우트·검색·지도·매매/전월세 조회는 변경하지 않음(예외: IMPLEMENTATION_PLAN 'Phase 1 연결 부위 예외'의 플래그로 감싼 탭 연결·개발 서버 경로). UI 탭 표시는 서버 상태 API(`/api/v2/analysis/apartments/{id}/status`, OFF면 404)로 판정. 별도 브랜치에서 검증 후 수동 승인. 공용 DB 장애는 Phase 1까지 영향을 줄 수 있으므로 쿼리 비용/인덱스/동시성 제한 필수.

## 성능 목표 (검증 전)
summary p95 800ms, monthly p95 800ms, areas p95 500ms, evidence p95 1000ms. EXPLAIN ANALYZE, 무료 DB 용량, cold start, 36개월 최대 요청, 동시성 측정. 불충족 시 인덱스/쿼리·캐시 최적화 제안, 비용 발생 옵션은 금지.
